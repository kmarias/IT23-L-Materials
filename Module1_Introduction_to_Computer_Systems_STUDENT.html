1What is a Computer System?

A computer is more than the box on the desk.

A computer is an electronic device that accepts data, processes it according to a set of instructions (a program), stores it, and produces useful output (information). The key word is programmable: the same machine can be a calculator, a typewriter, a video player, or a cash register depending on the instructions it runs.

A computer system is the complete working arrangement of everything needed for the computer to do useful work. It has four elements:

1. Hardware

The physical, tangible parts you can touch: keyboard, CPU, memory, monitor, cables.

Example: the laptop, the printer, the Wi-Fi router.

2. Software

The instructions (programs) that tell hardware what to do. You cannot touch software; you can only see its effects.

Example: Windows, Android, MS Word, Chrome, a mobile game.

3. Data

Raw facts the system works on: numbers, text, images, sound. Processed data becomes information.

Example: "95, 88, 90" (data) → "Average grade: 91" (information).

4. People (Peopleware)

Users, technicians, programmers, administrators — the humans who use, build, and maintain the system.

Example: the cashier, the student, the IT support staff.

Some textbooks list a fifth element: Procedures

Procedures are the documented steps people follow to use the system correctly — e.g., "how to enroll a student," "what to do when the network is down." Good procedures are what make a system reliable even when staff change.

Example: the school enrollment system

ElementIn the enrollment system
HardwareRegistrar's PCs, server, printer for the Certificate of Registration, network switches
SoftwareOperating system, the enrollment web application, database server (e.g., MySQL), browser
DataStudent name, ID number, subjects, units, fees, schedules
PeopleStudents, registrar staff, cashier, IT support, system administrator
ProceduresEnrollment flow: assessment → payment → printing of COR

Notice: if any element fails, the system fails. The server might be fine, but if the staff were never trained (people) or the student's ID was typed wrong (data), enrollment still breaks. IT professionals learn to look at all elements when solving problems.

2The Information Processing Cycle (IPOS)

Every computer, from a calculator to a supercomputer, follows the same basic cycle.

The IPOS cycle describes how data moves through a computer: it is Input, Processed, sent as Output, and Stored for later use. Many references add a fifth stage, Communication, because modern computers constantly exchange data over networks. Click each stage in the diagram to learn more.

Select a stage of the cycle to see its explanation and examples.

Example walkthrough: Buying load with an e-wallet

Input

You type the mobile number and amount (₱50) on the touchscreen and enter your MPIN. The touchscreen is an input device; the number, amount, and PIN are data.

Processing

The phone's processor runs the e-wallet app, which checks that the fields are valid (11-digit number, amount above the minimum) and encrypts the request before it leaves the phone.

Communication

The request travels over mobile data or Wi-Fi to the e-wallet company's servers. Their servers process it again: is the PIN correct? Is there enough balance? Then they contact the telco's system.

Storage

The transaction is recorded in the company's database (permanent storage) and your phone saves a copy in the transaction history.

Output

You see "Transaction successful" on screen, hear a notification sound, and receive an SMS. The output is now information you can act on.

3Computer Hardware

The physical components, grouped by the job they do.

Hardware refers to all physical components of a computer system. It is easiest to understand hardware by function — what part of the IPOS cycle does the device serve? Some devices serve more than one function (a touchscreen is both input and output).

Input devices convert things humans (or the environment) produce into digital signals the computer understands.

  • Keyboard – text and commands. Types: membrane (cheap, quiet) and mechanical (individual switches, durable).
  • Pointing devices – mouse (optical/laser), touchpad, trackball, stylus.
  • Scanners and readers – flatbed scanner, barcode reader (grocery POS), QR scanner, biometric fingerprint reader (attendance/DTR systems).
  • Audio/visual input – microphone, webcam, digital camera.
  • Sensors – temperature, motion, GPS, accelerometer in phones.

Key idea: input devices perform analog-to-digital conversion. Your voice is a continuous sound wave; the microphone and sound chip turn it into numbers.

The Central Processing Unit (CPU) is the "brain" that executes instructions. Inside it:

  • Control Unit (CU) – fetches instructions from memory, decodes them, and directs other parts.
  • Arithmetic Logic Unit (ALU) – performs math (add, subtract) and logic (compare: is A > B?).
  • Registers – tiny, ultra-fast storage locations inside the CPU holding the data currently being worked on.
  • Cache – small, fast memory (L1, L2, L3) that keeps frequently used data close to the cores.

The CPU repeats the machine cycle billions of times per second: Fetch → Decode → Execute → Store.

  • Clock speed (GHz) – cycles per second. 3.5 GHz = 3.5 billion cycles per second.
  • Cores – independent processing units on one chip; a quad-core CPU can work on four tasks at once.
  • Threads – with technologies like Hyper-Threading/SMT, one core can handle two streams of instructions.

Other processors: the GPU (Graphics Processing Unit) handles thousands of simple calculations in parallel — ideal for graphics, video, and AI. Phones use an SoC (System on a Chip) that combines CPU, GPU, modem, and more on one chip.

Primary memory holds the programs and data the CPU is using right now.

  • RAM (Random Access Memory) – read/write working memory. Volatile: contents disappear when power is cut. That is why unsaved work is lost in a brownout.
  • ROM (Read-Only Memory) – non-volatile; holds firmware such as the BIOS/UEFI. Modern "ROM" is usually flash memory that can be updated.
  • Cache – very fast memory between CPU and RAM.

Analogy: Storage is your bag (holds everything, but you have to dig into it). RAM is your desk (only what you're working on, but instantly reachable). Registers are your hands. A bigger desk (more RAM) lets you work on more things at once without going back to the bag.

Secondary storage keeps data permanently (non-volatile), even without power.

  • HDD (Hard Disk Drive) – magnetic spinning platters and a moving read/write head. Large and cheap per GB, but slower and sensitive to shock.
  • SSD (Solid State Drive) – flash memory, no moving parts. Much faster, silent, shock-resistant. Comes in 2.5" SATA and M.2 NVMe forms.
  • Removable – USB flash drives, SD/microSD cards, external drives.
  • Optical – CD, DVD, Blu-ray (now rare but still used for archives).
  • Cloud storage – Google Drive, OneDrive: your data is stored on someone else's servers and accessed over the internet.

Output devices turn digital results into something humans can perceive.

  • Monitors – LCD/LED, OLED. Key specs: resolution (1920×1080), refresh rate (60/144 Hz), size (diagonal inches), panel type (IPS, VA, TN).
  • Printers – inkjet (ink tank printers are common in PH shops), laser (fast, cheap per page), dot-matrix (still used for multi-part forms and receipts), thermal (POS receipts).
  • Audio – speakers, headphones.
  • Projectors – classroom displays.
  • Others – 3D printers, haptic feedback (phone vibration), plotters.

Communication devices let computers exchange data.

  • NIC (Network Interface Card) – wired Ethernet port (RJ-45) or wireless adapter (Wi-Fi).
  • Modem / ONT – connects your home to the internet provider (fiber ONT for fiber connections).
  • Router – directs traffic between networks; home routers also provide Wi-Fi.
  • Switch – connects many wired devices within a local network (computer lab).
  • Bluetooth – short-range connection for headsets, mice, phones.

Peripheral vs. internal components

A peripheral is any device connected to the computer but not part of its core (keyboard, printer, external drive). Internal components are inside the case: motherboard, CPU, RAM, storage, power supply. You will study internal components in detail in Module 2.

4How Computers Represent and Store Data

Bits, bytes, and the memory hierarchy.

Computers are built from billions of tiny electronic switches (transistors) that are either on or off. We represent these two states as 1 and 0. One such digit is a bit (binary digit). Everything — text, photos, music, programs — is ultimately stored as patterns of bits.

Why does my "1 TB" drive show only 931 GB?

Drive makers use decimal units (1 TB = 1,000,000,000,000 bytes). Windows calculates in binary units (1 GiB = 1,073,741,824 bytes) but labels them "GB". 1,000,000,000,000 ÷ 1,073,741,824 ≈ 931. Nothing is missing — it is a difference in counting. Try it below.

The memory hierarchy

No single type of memory is fast, large, cheap, and permanent. So computers use a hierarchy: small and very fast at the top, large and slower at the bottom.

When you open a program, it is copied from storage into RAM; the CPU pulls the parts it needs into cache and registers. If RAM runs out, Windows uses part of the drive as "virtual memory" (the page file) — this is why a PC with too little RAM slows down dramatically when many browser tabs are open.

5Computer Software

The instructions that make hardware useful.

Software is a set of programs, procedures, and data that tell the hardware what to do. A program is a sequence of instructions written by programmers in a programming language (C, Java, Python, PHP), which is then translated into machine code the CPU can execute.

The layers of a computer system

Software is organized in layers. Each layer hides the complexity of the layer below it. Click a layer.

Select a layer to see what it does.

Categories of software

System software manages the computer itself and provides a platform for applications.

Operating System (OS)

Examples: Windows 11, macOS, Linux distributions (Ubuntu, Fedora), Android, iOS, ChromeOS. Core functions:

  • Process management – decides which program gets CPU time (multitasking).
  • Memory management – allocates RAM to programs and keeps them from overwriting each other.
  • File management – organizes data into files and folders using a file system (NTFS, FAT32, exFAT, ext4).
  • Device management – communicates with hardware through drivers.
  • Security – user accounts, passwords, permissions.
  • User interface – GUI (windows, icons) or CLI (Command Prompt, Terminal).

Utility software

Maintains and protects the system: antivirus/Windows Security, disk cleanup, defragmenter (for HDDs only), backup tools, file compression (7-Zip, WinRAR), disk partitioning tools.

Device drivers

Small programs that let the OS "talk" to a specific piece of hardware. A printer without the right driver may print garbage characters or not at all. Missing drivers show as yellow warning icons in Device Manager.

Application software helps users do specific tasks.

  • Productivity – word processors (Word, Google Docs), spreadsheets (Excel), presentations (PowerPoint, Canva).
  • Communication – email, Messenger, Zoom, Google Meet.
  • Web browsers – Chrome, Edge, Firefox.
  • Multimedia – VLC, Photoshop, CapCut.
  • Specialized / enterprise – POS systems, school management systems, hospital information systems, accounting software.
  • Mobile apps – e-wallets, delivery apps, games.

Installed vs. web-based: Installed apps run directly on your device. Web-based apps run in the browser and are hosted on a server (e.g., Google Docs, a PHP-based enrollment portal). SaaS (Software as a Service) is web software you subscribe to.

Programming (development) software is used to create other software.

  • Text editors and IDEs – VS Code, NetBeans, IntelliJ, Android Studio.
  • Compilers – translate the whole program into machine code before running (C, C++).
  • Interpreters – translate and run line-by-line (Python, PHP).
  • Debuggers – help find and fix errors.
  • Version control – Git/GitHub to track changes.

Firmware sits between hardware and software: it is software permanently stored on a chip inside the hardware.

  • BIOS / UEFI on the motherboard – tests hardware at startup (POST) and starts the OS loader. UEFI is the modern replacement for BIOS: graphical, supports drives larger than 2 TB (GPT), Secure Boot, and mouse input.
  • Firmware is also found in routers, printers, SSDs, keyboards, smart TVs.
  • Firmware updates fix bugs and security issues, but must never be interrupted — a power loss during a BIOS update can make the board unbootable ("bricked").

Software licensing

When you "buy" software, you usually buy a license — permission to use it under certain terms (the EULA, End User License Agreement).

Professional note: pirated software

Installing "cracked" software violates the Intellectual Property Code of the Philippines (RA 8293). It is also a major source of malware — many cracks and "activators" carry trojans and ransomware. IT professionals should recommend licensed or free/open-source alternatives.

6How Hardware and Software Work Together

Neither is useful alone.

Hardware without software is just metal and silicon. Software without hardware has nothing to run on. Let's trace two everyday situations.

Situation A: What happens when you press the power button? (The boot process)

1. Power on

The power supply (PSU) converts AC wall power to the DC voltages the components need. When voltages are stable, it sends a "Power Good" signal to the motherboard and the CPU is allowed to start.

2. Firmware starts (BIOS/UEFI)

The CPU runs its first instruction from the firmware chip on the motherboard. The firmware is the first software that ever runs.

3. POST (Power-On Self-Test)

The firmware checks essential hardware: CPU, RAM, video, keyboard. One short beep (on many boards) means OK. Other beep patterns or a blank screen point to a hardware fault — e.g., repeated long beeps often mean a RAM problem. (Beep codes differ by manufacturer.)

4. Find a boot device

The firmware checks the boot order (SSD, USB, network) and finds a drive with a bootloader. If none is found you'll see messages like "No bootable device" or "Reboot and select proper boot device."

5. Bootloader

The bootloader (Windows Boot Manager, GRUB for Linux) loads the operating system's core — the kernel — from storage into RAM.

6. Kernel and drivers load

The kernel takes control, loads device drivers, and starts background services (network, audio, antivirus).

7. Login and desktop

The login screen appears. After you sign in, your user profile, desktop, and startup programs load. Too many startup programs = slow boot.

Troubleshooting connection

Knowing these steps tells you where a problem is. No lights or fans = power stage. Beeps/no display = POST (hardware). "No bootable device" = storage or boot order. Blue screen during loading = drivers or OS. Slow after login = startup programs or malware.

Situation B: You type the letter "A" in a document

  1. You press the key; the keyboard's controller detects the key and sends a scan code through USB.
  2. The USB controller on the motherboard signals the CPU with an interrupt ("pay attention!").
  3. The keyboard driver in the OS translates the scan code into the character "A" based on your keyboard layout.
  4. The OS delivers the character to the active application (Word).
  5. Word adds the character to the document in RAM and asks the OS to redraw the screen.
  6. The graphics driver and GPU draw the letter, and the monitor displays it — all in a few milliseconds.

Every layer from the diagram above was used. If any layer fails (broken key, missing driver, frozen app), the letter never appears.

8Roles of IT Support

The people who keep users productive.

IT Support (also called Technical Support, Help Desk, or Service Desk) is the team that helps users when technology does not work as expected. They are usually the first point of contact between users and the IT department. Their goal is to restore normal service as quickly as possible with minimal impact on the organization.

Typical responsibilities

User assistance

Answer calls, chats, emails, and walk-ins; guide users through problems; reset passwords; unlock accounts.

Hardware support

Set up new PCs and peripherals, replace faulty parts (RAM, drives, keyboards), fix printers, manage the computer lab.

Software support

Install and update applications and OS, remove malware, fix application errors, configure email.

Basic networking

Check cables, reconnect Wi-Fi, verify IP settings, identify whether "no internet" is local or provider-wide.

Ticket management

Log every issue, prioritize, update status, and document the solution in the knowledge base.

Asset & inventory

Track equipment (serial numbers, property tags), licenses, and warranty information.

User training

Teach users how to use systems properly and avoid security risks (phishing, weak passwords).

Escalation

Recognize when a problem is beyond their level and pass it to the right specialist with complete notes.

The support tiers

Most organizations organize support into tiers (levels). Simple problems are solved quickly at lower tiers; complex ones are escalated.

Tier 0 – Self-service

Users solve problems themselves using FAQs, knowledge base articles, password-reset portals, chatbots. Example: "Forgot password? Click here."

Tier 1 – Help desk / first line

Handles common, well-documented problems using scripts and checklists: password resets, printer jams, Wi-Fi reconnection, basic software installs. Collects information and creates the ticket. Goal: resolve on first contact. Entry-level position for new IT graduates.

Tier 2 – Technical support / desktop support

More experienced technicians who handle problems Tier 1 could not solve: hardware replacement, OS reinstallation, driver conflicts, malware removal, network configuration of a workstation. Often goes on-site to the user's desk.

Tier 3 – Expert / engineering

Specialists such as system administrators, network engineers, database administrators, and developers. They handle server failures, network outages, bugs in custom software, and root-cause analysis.

Tier 4 – External / vendor support

Problems outside the organization's control: hardware under manufacturer warranty, software bugs needing the vendor's fix, internet outages handled by the ISP.

The life of a support ticket

A ticket is a record of a user's request or problem in a ticketing system (e.g., osTicket, GLPI, Jira Service Management, Freshdesk). Tickets make support measurable and accountable.

Skills of an effective IT support specialist

Technical skills

Hardware assembly and repair, OS installation, basic networking, troubleshooting, security awareness, familiarity with Microsoft 365/Google Workspace.

Communication

Explain technical things in plain language. Ask good questions. Avoid jargon: say "the program that runs your computer" instead of "the kernel."

Customer service

Patience, empathy, politeness — especially when users are stressed. Listen fully before acting.

Documentation

Write clear ticket notes so the next technician understands what was done.

Example: a good vs. a poor help desk response

User: "The internet is broken again!! I have a report due."

Poor: "It's working on my end. Restart your PC." (dismissive, no investigation)

Good: "I understand you have a deadline — let's fix this quickly. Are other websites loading, or none at all? Are you on Wi-Fi or a cable? Do you see an icon with a yellow triangle at the bottom-right of the screen?" (acknowledges feelings, asks targeted questions, gathers information)

9Roles of System Administrators

The people who keep the systems themselves running.

A System Administrator ("sysadmin") is responsible for the configuration, upkeep, and reliable operation of computer systems, especially servers and multi-user systems. If IT Support focuses on users, sysadmins focus on the infrastructure those users depend on.

Core responsibilities

Install, configure, and maintain servers – physical and virtual (VMware, Hyper-V, Proxmox) and cloud (AWS, Azure, Google Cloud). Typical server roles: file server, web server (Apache, Nginx, IIS), database server (MySQL, PostgreSQL, SQL Server), email server, DHCP and DNS, print server.

Example: Setting up a Linux server with Apache, PHP, and MySQL so the school's enrollment portal can run.

Manage user accounts and permissions – create, modify, and disable accounts; assign users to groups; control who can access what. In Windows networks this is done with Active Directory; in Linux with useradd, groups, and file permissions.

Principle of least privilege: give each user only the access they need to do their job. A student assistant does not need administrator rights.

Example: When a faculty member resigns, the sysadmin disables the account on the last day so former staff cannot access student records.

Back up data and plan for disasters. Hardware fails, ransomware strikes, typhoons flood server rooms. Sysadmins schedule backups and — just as important — test restoring them.

The 3-2-1 backup rule: keep 3 copies of data, on 2 different types of media, with 1 copy off-site (or in the cloud).

Backup types: full (everything), incremental (changes since the last backup of any kind), differential (changes since the last full backup).

A Disaster Recovery Plan (DRP) documents how to restore services after a major event.

Keep systems secure – apply OS and software updates (patches), configure firewalls, manage antivirus/endpoint protection, enforce password policies, enable multi-factor authentication, review logs for suspicious activity.

Most successful attacks exploit vulnerabilities for which a patch already existed. Patch management is routine but critical work.

Monitor performance and availability – CPU, RAM, disk space, network traffic, service uptime. Tools: Task Manager/Resource Monitor, Linux top/htop, and monitoring systems like Zabbix, Nagios, or PRTG that send alerts.

Example: An alert at 85% disk usage on the database server lets the sysadmin add space before the enrollment system crashes during peak season.

Document everything – network diagrams, server configurations, passwords (in a secure password manager), procedures, change logs. Good documentation lets someone else recover the system if the sysadmin is absent.

Sysadmins also automate repetitive tasks using scripts (PowerShell, Bash, Python).

10The Troubleshooting Methodology

The core skill shared by IT support and sysadmins.

Good technicians don't guess randomly. They follow a structured process. The widely used CompTIA troubleshooting methodology has six steps (paraphrased here):

  1. Identify the problem – gather information from the user, ask what changed recently, try to reproduce the issue, check error messages and logs, back up data before making changes.
  2. Establish a theory of probable cause – start with the simple and obvious ("Is it plugged in?"). Question the obvious. Research if needed.
  3. Test the theory – if confirmed, plan the fix. If not, form a new theory or escalate.
  4. Establish a plan of action and implement the solution – consider the impact on the user and organization; follow company policy.
  5. Verify full system functionality – confirm the problem is fixed and nothing else broke; implement preventive measures if possible.
  6. Document findings, actions, and outcomes – so the next person can solve it faster.

Worked example

"The lab printer won't print."
  1. Identify: Ask: Is it one PC or all PCs? Any error on the printer display? Answer: all PCs; printer shows "Ready". Recent change? A new router was installed yesterday.
  2. Theory: The new router gave the printer a different IP address, so PCs are sending jobs to the old address.
  3. Test: Print the printer's network configuration page — the IP changed from .50 to .103. Theory confirmed.
  4. Plan & implement: Reserve a fixed IP (.50) for the printer in the router's DHCP settings and restart the printer.
  5. Verify: Print a test page from three different PCs. Preventive: document the reservation.
  6. Document: Update the ticket and network notes: "Printer uses DHCP reservation 192.168.1.50."

Professional ethics and responsibilities

IT personnel often have access to everything: emails, grades, payroll, personal files. With that access comes responsibility.

Confidentiality

Never open, copy, or share users' files beyond what the task requires. A technician fixing a laptop has no reason to browse its photos.

Data Privacy Act (RA 10173)

Philippine law protecting personal information. Organizations must safeguard personal data; unauthorized access or disclosure can lead to penalties.

Cybercrime Prevention Act (RA 10175)

Illegal access, data interference, and system interference are crimes — even "just testing" someone's account without permission.

Honesty & accountability

Admit mistakes immediately (e.g., accidentally deleting a folder) so recovery can start. Hiding errors makes them worse.

Use of admin rights

Use privileged accounts only for administrative tasks; never to snoop, bypass policy, or for personal benefit.

Respect & professionalism

Treat all users with respect regardless of their technical skill. Dress and act appropriately when visiting offices.

Instructions

👥 Groups of 4–5⏱ 20 minutes

  1. The teacher assigns one case to each group (cases may repeat across groups).
  2. Do not open the discussion points yet. As a group, answer: (a) What is the ethical problem? (b) Who could be harmed? (c) What should the IT person do, and which law or principle applies?
  3. After 10 minutes, open your case to compare your answers with the discussion points.
  4. Choose a reporter to share your group's answer with the class in 2 minutes.

Output: Group answers to questions (a)–(c) and a 2-minute report.

Case 1: While repairing a teacher's laptop, you see an open folder named "Final Exam Answers."

Discussion points: You must not open, copy, or share it. Viewing it is outside the task, and sharing it would be a serious breach of trust and school policy. Focus only on the repair.

Case 2: Your friend asks you to use your admin access to change their grade "just by one point."

Discussion points: This is unauthorized data modification — potentially a violation of RA 10175 and grounds for dismissal. Refuse clearly; consider reporting the request.

Case 3: You accidentally deleted a shared folder while cleaning a server.

Discussion points: Report it immediately to your supervisor, restore from backup, document what happened, and suggest a safeguard (e.g., confirmation steps, restricted permissions). Hiding it delays recovery and destroys trust.

Case 4: A user asks you to install a cracked version of expensive software "because everyone does it."

Discussion points: Decline: it's illegal under RA 8293 and a major malware risk. Offer legal options: free/open-source alternatives, education licenses, or requesting a purchase.

12Summary

Key takeaways
  • A computer system = hardware + software + data + people (+ procedures).
  • All computers follow the Input → Process → Output → Storage cycle, plus communication.
  • System software runs the computer; application software serves the user; firmware starts the hardware.
  • IT Support restores service for users; System Administrators keep the infrastructure reliable and secure.
  • Structured troubleshooting and professional ethics are what separate a professional from a guesser.
